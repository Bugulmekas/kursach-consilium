# Инструкция: как довести курсовую или диплом до защиты

Это не готовая работа и не чужой проект. Это **методика и инструменты**: как проверить свой `.docx`, провести консилиум, внести правки, собрать рамки и штампы, проверить библиографию и не потерять вёрстку.

Все примеры обезличены. Никаких чужих текстов, ФИО, групп и тем здесь нет — только порядок действий, который можно применить к своей работе.

---

## 0. Для кого

- Студент, который пишет курсовую/диплом и хочет довести оформление до требований.
- Студент, который получил замечания и не понимает, с чего начать.
- Преподаватель или тьютор, которому нужен воспроизводимый чек-лист проверки.
- Всем, кто автоматизирует Word через MCP/COM и хочет безопасный сценарий.

## 1. Принципы

1. **Сначала смысл, потом вёрстка.** Рамки и штампы делаются после текста, иначе всё «поедет».
2. **Копия до правок.** Любой скрипт может испортить файл; копия — не паранойя.
3. **Не выдумывать результаты.** Если команда не выполнялась на стенде — это «рекомендуемая последовательность», а не «полученный результат».
4. **Не цитировать недоступное.** Источник, который не открывается, не должен попадать в список.
5. **Проверять глазами.** Автоматическая проверка не видит, что текст налез на штамп.
6. **Не менять порядок страниц без необходимости.** Титул, содержание и введение обычно уже стоят правильно; меняются рамки, штампы и содержимое.
7. **Академическая честность.** Инструменты помогают с оформлением и проверкой, а не пишут работу за вас. Если вуз требует раскрывать использование ИИ — раскройте.

## 3. Роли

| Роль | Что делает | Результат |
|---|---|---|
| **Методист** | проверяет форму: структура, объём, введение, заключение, оформление, список | вердикт + замечания |
| **Предметник** | проверяет содержание: техчасть, команды, конфиги, безопасность, ограничения | вердикт + замечания |
| **Агент по документации** | проверяет библиографию: ГОСТ, цитирование, дубли, доступность | карта цитирования |
| **Студент** | вносит правки и отвечает за смысл | исправленный документ |
| **Технический исполнитель** | Word, MCP, COM, python-docx, QA | скриншоты, отчёты |

Методист и предметник работают **независимо**. Второй не должен видеть вердикт первого до своего вывода — иначе замечания «подгоняются».

## 4. Фаза 0. Приёмка и диагностика

### 4.1. Копия

```powershell
Copy-Item "D:\work\thesis.docx" "D:\work\thesis.before.docx"
```

### 4.2. Открыть Word

Если Word показывает диалог о серьёзной ошибке при открытии — это флаг незавершённого восстановления, а не «битый файл». Снять:

```powershell
$word = New-Object -ComObject Word.Application
$word.Visible = $true
$doc = $word.Documents.Open($path)
$doc.Saved = $true
$doc.Close(0)
$word.Quit()
```

### 4.3. Посчитать факты

```powershell
python -X utf8 scripts\consilium\docx_tools.py info "D:\work\thesis.docx"
```

Что смотреть:

- число страниц;
- число секций (титул/содержание/приложение часто разбиты на секции);
- таблицы и рисунки;
- есть ли `titlePg` (особый титул);
- какие колонтитулы содержат `PAGE` и `NUMPAGES`.

### 4.4. Выгрузить текст

```powershell
python -X utf8 scripts\consilium\docx_tools.py text "D:\work\thesis.docx" --out dump.txt
```

Так удобнее искать дубли, старые фрагменты и расхождения, не листая Word.

**Гейт:** есть копия и стартовые цифры. Без этого не начинать правки.

## 5. Фаза 1. Консилиум

### 5.1. Промпт методисту

```text
Ты — методист кафедры. Проверь курсовой проект на соответствие методичке.
Дай вердикт: «Готов», «Готов с доработками» или «Не готов».
Не более 8 замечаний. Каждое: раздел/страница, что не так, что должно быть.
Проверь: структуру, объём, введение (цель, задачи, объект, предмет),
заключение (по задачам), оформление, рамки/штампы, список источников.
Не переписывай текст за студента.
```

### 5.2. Промпт предметнику

```text
Ты — преподаватель профильной дисциплины. Проверь техническую часть.
Дай вердикт: «Готов», «Готов с доработками» или «Не готов».
Не более 8 замечаний. Каждое: раздел, техническая ошибка, чем подтверждается.
Проверь: команды, конфиги, схему взаимодействия компонентов,
безопасность, резервное копирование, диагностику, ограничения.
Не выдумывай результаты, которых нет в документе.
```

### 5.3. Что обычно находят

| Категория | Типичное замечание |
|---|---|
| Структура | в заключении число глав не совпадает с фактическим |
| Дубли | один и тот же заголовок встречается дважды |
| Полнота | нет раздела сопровождения/резервного копирования |
| Техника | команды без пояснений, конфиги не согласованы между разделами |
| Безопасность | нет прав, портов, межсетевого экрана и их аналогов |
| Таблицы | нет подписей и подводок |
| Библиография | источники не по ГОСТ, есть нецитируемые |
| Титул | нет города/года, разнобой в группе |
| Оформление | штампы не по секциям, текст налезает |

**Гейт:** два независимых вердикта, замечания привязаны к разделам.

## 6. Фаза 2. Протокол разногласий

Спорные пункты сводятся в таблицу:

| № | Разногласие | Позиция A | Позиция B | Решение | Обоснование |
|---|---|---|---|---|---|

Типичные разногласия:

| Разногласие | Как решать |
|---|---|
| Нужен ли полный штамп на содержании | по эталону кафедры / решению руководителя |
| Сколько скриншотов оставить | столько, сколько нужно для доказательств; лишние — в приложение |
| Команды не выполнялись на стенде | оставить как «рекомендуемая последовательность», честно указать |
| Источник недоступен | исключить, даже если выглядит полезным |
| Поля не совпадают с рамкой | приоритет у рамки по ГОСТ 2.104 |
| Сокращать ли листинги | только если они не нужны для воспроизводимости |

Правило: решение принимается по методичке, ГОСТ или проверяемому факту. «Мне так удобнее» — не обоснование.

**Гейт:** по каждому разногласию есть решение и обоснование.

## 7. Фаза 3. Правки

### 7.1. Порядок

1. Текст и структура.
2. Команды, конфиги, таблицы.
3. Библиография.
4. Вёрстка.
5. QA.

### 7.2. Категории правок

| Категория | Что делать | Инструмент |
|---|---|---|
| Дубли заголовков | удалить лишний, проверить нумерацию | `docx_tools.py find/replace` |
| Расхождения в тексте | привести к одной версии | `replace` |
| Пустые разделы | добавить команды/пояснения | python-docx или Word |
| Таблицы без подписей | добавить «Таблица N – …» и подводку | python-docx |
| Старые фрагменты | удалить, а не закомментировать | `replace` |
| Библиография | ГОСТ, цитирование, дубли | `qa_docx.py`, вручную |
| Титул | город, год, группа, подписи | Word |
| Штампы | секции, `PAGE`, `NUMPAGES`, цвет | Word + COM |

### 7.3. Безопасная замена текста

```powershell
python -X utf8 scripts\consilium\docx_tools.py replace "D:\work\thesis.docx" "старая фраза" "новая фраза"
```

Что делает скрипт:

- создаёт резервную копию;
- ищет фразу в абзацах;
- заменяет текст, сохраняя `pPr` и последний run;
- по умолчанию не трогает оглавление.

Ограничение: если внутри абзаца были разные начертания, абзац станет однородным. Для сложных абзацев лучше править в Word вручную или использовать python-docx с точечной вставкой run'ов.

### 7.4. Вставка абзацев и таблиц

Word закрыт. Новый абзац наследует `w:pPr` и `w:rPr` соседнего:

```python
ppr = re.search(r'<w:pPr>.*?</w:pPr>', neighbor, re.S).group(0)
rpr = re.search(r'<w:rPr>.*?</w:rPr>', neighbor_run, re.S).group(0)

new_p = (
    '<w:p>' + ppr +
    '<w:r>' + rpr +
    '<w:t xml:space="preserve">' + escape(text) + '</w:t>' +
    '</w:r></w:p>'
)
```

Почему так: если собрать абзац «с нуля», он получит шрифт по умолчанию и выбьется из документа.

**Гейт:** документ открывается, старые фрагменты удалены, новые — на месте.

## 8. Фаза 4. Рамки и штампы

### 8.1. Схема

| Секция | Что входит | Колонтитул |
|---|---|---|
| 1 | титул + содержание | титул — без штампа; содержание — по требованию кафедры |
| 2 | введение … заключение | нижняя полоса «Лист N» |
| 3 | приложение | полоса наследуется |

Полный штамп: `PAGE` для «Лист» и `NUMPAGES` для «Листов». Полоса: только `PAGE`.

### 8.2. Почему не меняют страницы местами

Обмен страниц требует:

- разрывать секции;
- переносить `titlePg`;
- заново привязывать `header/footer`;
- пересчитывать поля и оглавление.

Обычно дешевле оставить порядок и заменить только штампы. Если руководитель требует иначе — сначала согласуйте, потом ломайте секции.

### 8.3. Проверка

1. Титул — без штампа.
2. Содержание — как требует кафедра.
3. С 3-й страницы — полоса «Лист N».
4. Приложение — в своей секции.
5. Реквизиты и ФИО — чёрные.
6. Текст не налезает на штамп.
7. Нумерация совпадает с оглавлением.

**Гейт:** скриншоты контрольных страниц подтверждают схему.

## 9. Фаза 5. Библиография

Правила:

- ГОСТ Р 7.0.100-2018 (или требование кафедры).
- Каждый источник цитируется.
- Дубли сливаются.
- Недоступные домены исключаются.
- Нумерация в тексте соответствует списку.
- Старые диапазоны ссылок не остаются.

Проверка:

```powershell
python -X utf8 scripts\consilium\docx_tools.py citations "D:\work\thesis.docx" --sources 20
```

Скрипт покажет использованные номера, нецитируемые источники и номера вне диапазона.

## 10. Фаза 6. QA

```powershell
python -X utf8 scripts\consilium\qa_docx.py "D:\work\thesis.docx" --sources 20 --require-stamp
```

Что проверяется:

- страницы, секции, таблицы, рисунки;
- заглушки (`TODO`, «Ваша тема», `???`);
- покрытие ссылок `[n]`;
- дубли заголовков (с оговоркой про оглавление);
- подписи таблиц и рисунков;
- красный текст;
- поля `PAGE`/`NUMPAGES`;
- обязательные и запрещённые фразы.

Настройки можно вынести в JSON:

```json
{
  "sources": 20,
  "require": ["ПРИЛОЖЕНИЕ А"],
  "forbid": ["TODO", "Ваша тема"],
  "require_stamp": true
}
```

```powershell
python -X utf8 scripts\consilium\qa_docx.py thesis.docx --config qa.json
```

**Гейт:** нет FAIL. WARN — проверить глазами.

Полный набор ручных проверок — в [чек-листе](03-CHECKLIST.md).

## 11. Финализация

```powershell
powershell -ExecutionPolicy Bypass -File scripts\word-com\update_fields.ps1 -Path "D:\work\thesis.docx"
```

Скрипт:

- обновляет поля;
- обновляет оглавление **дважды**;
- пересчитывает страницы;
- сохраняет;
- закрывает Word.

Затем:

1. Открыть заново.
2. Пролистать контрольные страницы.
3. Снять скриншоты.
4. Убедиться, что нет диалога восстановления.
5. Проверить, что нумерация совпадает с оглавлением.

Word может помечать документ «несохранённым» из-за полей — это нормально, содержимое не меняется.

---

## 12. Ограничения

- Скрипты не понимают смысл. Они не проверят, верна ли формула и достигнута ли цель.
- Автоматическая проверка не видит наложение текста на штамп — нужен глаз.
- `docx_tools.py replace` делает абзац однородным по форматированию.
- ГОСТ 2.104 и требования кафедры могут расходиться; приоритет — у требований кафедры.
- Если работа уже принята руководителем, любые изменения — только после согласования.

---

## 13. Воспроизведение за 10 шагов

1. Сделать копию.
2. Открыть Word, снять флаг восстановления.
3. Посчитать страницы, секции, таблицы, рисунки.
4. Провести два независимых вердикта.
5. Свести разногласия в протокол.
6. Внести текстовые правки.
7. Пересобрать таблицы и библиографию.
8. Проверить рамки и штампы глазами.
9. Прогнать QA и обновить поля.
10. Сохранить, закрыть, открыть, пролистать.
