# Скил: консилиум и доведение курсовой до защиты

## Когда применять

- Курсовая или диплом в `.docx` требуют проверки по методичке и доведения до защиты.
- Есть замечания преподавателя, но непонятно, что и в каком порядке править.
- Нужно привести в порядок рамки, штампы, секции, оглавление, библиографию.
- Нужно повторить процесс: два рецензента → протокол → правки → QA.

Не применять для:

- простой вычитки без оформления;
- работы, где неизвестны требования кафедры (сначала запросить);
- «написать работу за студента» — скил помогает с оформлением и проверкой, а не с содержанием.

## Входы

| Вход | Обязателен | Комментарий |
|---|---|---|
| `.docx` работы | да | сделать копию до правок |
| методичка / требования кафедры | да | объём, структура, оформление, библиография |
| эталон рамок/штампов | желательно | иначе ГОСТ 2.104 |
| тема, ФИО, группа, дисциплина | да | титул и штампы |
| список источников | да | или время на сбор |

## Роли

1. **Методист** — форма: структура, объём, введение, заключение, оформление, список.
2. **Предметник** — содержание: техчасть, команды, конфиги, безопасность, ограничения.
3. **Агент по документации** — библиография, ГОСТ, цитирование, доступность.
4. **Студент** — вносит правки и отвечает за смысл.
5. **Технический исполнитель** — Word, MCP, COM, python-docx, QA.

Методист и предметник работают **независимо**. Нельзя показывать второму вердикт первого до его собственного вывода.

## Фаза 0. Приёмка

1. Сделать копию: `thesis.before.docx`.
2. Открыть Word. Если диалог о серьёзной ошибке — снять флаг восстановления:
   ```powershell
   $doc = $word.Documents.Open($path)
   $doc.Saved = $true
   $doc.Close(0)
   ```
3. Посчитать факты:
   ```powershell
   python -X utf8 scripts\consilium\docx_tools.py info thesis.docx
   ```
4. Выгрузить текст:
   ```powershell
   python -X utf8 scripts\consilium\docx_tools.py text thesis.docx --out dump.txt
   ```

Зафиксировать: страницы, секции, таблицы, рисунки, где штампы, какие дубли и старые фрагменты.

**Гейт:** есть копия и стартовые цифры.

## Фаза 1. Два вердикта

### Промпт методисту

```text
Ты — методист кафедры. Проверь работу на соответствие методичке.
Дай вердикт: «Готов», «Готов с доработками» или «Не готов».
Не более 8 замечаний. Каждое: раздел/страница, что не так, что должно быть.
Проверь: структуру, объём, введение (цель, задачи, объект, предмет),
заключение (по задачам), оформление, рамки/штампы, список источников.
Не переписывай текст за студента.
```

### Промпт предметнику

```text
Ты — преподаватель профильной дисциплины. Проверь техническую часть.
Дай вердикт: «Готов», «Готов с доработками» или «Не готов».
Не более 8 замечаний. Каждое: раздел, техническая ошибка, чем подтверждается.
Проверь: команды, конфиги, схему взаимодействия компонентов,
безопасность, резервное копирование, диагностику, ограничения.
Не выдумывай результаты, которых нет в документе.
```

**Гейт:** оба вердикта получены независимо, замечания привязаны к разделам.

## Фаза 2. Протокол разногласий

| № | Разногласие | Позиция A | Позиция B | Решение | Обоснование |
|---|---|---|---|---|---|

Правила:

- решение — по методичке, ГОСТ или проверяемому факту;
- недоступный источник не цитируется;
- команда, не выполненная на стенде, оформляется как «рекомендуемая последовательность»;
- сокращение доказательств (скриншотов, листингов) — только с обоснованием.

**Гейт:** по каждому разногласию есть решение и обоснование.

## Фаза 3. Правки

Порядок строгий:

1. **Текст и структура** — смысл.
2. **Команды, конфиги, таблицы** — в исправленные разделы.
3. **Библиография** — когда понятно, что цитируется.
4. **Вёрстка** — после текста.
5. **QA** — после вёрстки.

### Текст

```powershell
python -X utf8 scripts\consilium\docx_tools.py replace thesis.docx "старая фраза" "новая фраза"
```

- искать точную фразу;
- дробить длинные замены;
- по умолчанию оглавление не трогается;
- после пачки правок — проверить, что документ открывается.

### Абзацы и таблицы

- Word закрыт.
- python-docx или прямая правка `word/document.xml`.
- Новый абзац наследует `w:pPr` и `w:rPr` соседнего.
- Текст — в `w:t` с `xml:space="preserve"`.

### Библиография

- ГОСТ Р 7.0.100-2018 или требование кафедры.
- Каждый источник цитируется.
- Дубли сливаются.
- Недоступные домены исключаются.
- Старые диапазоны ссылок не остаются.

**Гейт:** документ открывается, все правки на месте.

## Фаза 4. Вёрстка

1. Схема секций:
   - титул — без штампа;
   - содержание — по требованию кафедры;
   - с 3-й страницы — полоса «Лист N»;
   - приложение — своя секция.
2. Полный штамп: `PAGE` для «Лист», `NUMPAGES` для «Листов».
3. Полоса: только `PAGE`.
4. Реквизиты и ФИО — чёрные.
5. Текст не налезает на штамп.
6. **Не менять страницы местами** без необходимости — только рамки/штампы/содержимое.

**Гейт:** скриншоты титула, содержания, body и приложения подтверждают схему.

---

## Фаза 5. QA

```powershell
python -X utf8 scripts\consilium\qa_docx.py thesis.docx --sources 20 --require-stamp
```

Проверяется:

- страницы, секции, таблицы, рисунки;
- заглушки;
- покрытие ссылок `[n]`;
- дубли заголовков (с оговоркой про оглавление);
- подписи таблиц и рисунков;
- красный текст;
- поля `PAGE`/`NUMPAGES`;
- обязательные и запрещённые фразы.

Конфиг:

```json
{
  "sources": 20,
  "require": ["ПРИЛОЖЕНИЕ А"],
  "forbid": ["TODO", "Ваша тема"],
  "require_stamp": true
}
```

**Гейт:** нет FAIL. WARN — проверить глазами.

## Фаза 6. Финализация

```powershell
powershell -ExecutionPolicy Bypass -File scripts\word-com\update_fields.ps1 -Path thesis.docx
```

Затем:

1. Закрыть Word.
2. Открыть заново.
3. Пролистать контрольные страницы.
4. Снять скриншоты.
5. Проверить, что файл не просит восстановление.

**Гейт:** документ открывается с первого раза, страницы совпадают с оглавлением.

## Грабли

| Грабля | Решение |
|---|---|
| Word «зависает» на открытии | снять флаг восстановления |
| `foreach` по COM-коллекции не работает | только `.Item(i)` |
| Кириллица в inline-PowerShell ломается | `.ps1` в UTF-8 с BOM |
| `insert_paragraphs` вставляет по курсору | файловые вставки — python-docx при закрытом Word |
| Файловые инструменты читают старую версию | сохранить Word или использовать `word_live_*` |
| Оглавление съехало | обновить дважды + `Repaginate` |
| Документ «не сохранён» после открытия | поля; сохранить явно |
| Word перенумеровал header/footer | сверять по содержимому |

## Чего не делать

- Не менять страницы местами без необходимости.
- Не выдумывать результаты.
- Не цитировать недоступные источники.
- Не сокращать доказательства без обоснования.
- Не править вёрстку до текста.
- Не запускать массовые правки без копии.
- Не выдавать работу, сделанную ИИ, за свою, если это запрещено правилами вуза.

## Выходы

- исправленный `.docx`;
- протокол консилиума с решениями;
- QA-отчёт;
- скриншоты контрольных страниц.
